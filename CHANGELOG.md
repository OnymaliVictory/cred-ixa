# Creditxa — Changelog (bug fixes + new features)

## 🗄️ Database (`creditxa-supabase.sql` — completely rewritten)

- **Security bug:** the anon API key could previously read and write *every
  row of every table* — every client's name, NIF, income, IBAN, and every
  other applicant's data was fully exposed to anyone who opened the browser's
  network tab. Row Level Security now actually restricts data: clients can
  only see their own records, admins need a verified account.
- **Security bug:** admin login was a hard-coded email/password sitting in
  plaintext in the HTML source (and the login screen literally printed the
  password on-screen as a "default credentials" hint). Replaced with real
  Supabase Auth, linked to an `admin_users` table via a database function
  (`admin_login_check()`).
- **New:** `activity_log` now records client account activity (signup, email
  verified, login, logout) in addition to admin actions, tagged with an
  `actor_type` column, so it can power a real admin-facing activity feed.
- **New:** public loan submissions and admin client-creation now go through
  validated `submit_loan_application()` / `admin_create_client()` database
  functions instead of raw table writes — this closes the door on a browser
  being able to insert arbitrary/malformed records directly.
- **Bug:** application numbers and client codes were generated with
  `Date.now()` in the browser — a real (if rare) collision/race condition.
  Now generated by database sequences.
- **New:** the script always drops every object it created before recreating
  them, so it can be re-pasted at any time to fully reset the database — as
  requested.

## `assets/js/application-modal.js`

- Rewrote the submission flow to call the new secure
  `submit_loan_application()` RPC instead of doing a three-step
  find/insert/update dance directly against the `clients` and
  `loan_applications` tables from the browser.

## `assets/js/main.js`

- **Bug:** the homepage's main "Pedir Este Crédito" button had **two**
  conflicting click handlers — a fake one here that showed a spinner and a
  canned "Pedido Enviado" success message, *and* the real one in `index.html`
  that opens the actual application modal. Clicking it fired both at once.
  Removed the fake handler.
- **Bug:** there were **two** submit handlers on the newsletter form — a real
  one in `index.html` that inserts into Supabase, and a fake one here that
  reset the form and showed a generic success toast regardless of whether the
  real signup actually succeeded or failed. Removed the fake handler.
- **Bug:** the scroll handler and header setup assumed a `.header` element
  always exists and would throw (silently breaking every other script on the
  page, including the FAQ accordion and testimonial slider) if it didn't.
  Added null-guards.

## `pages/login.html`

- Signup, login, and logout now write real entries to `activity_log` so
  admins can see them (signup/verification are logged automatically by
  database triggers; login/logout call a small `log_activity()` RPC).
- **Bug:** switching between the "Iniciar Sessão" and "Criar Conta" tabs left
  red field-error borders from the previous tab visible. Now cleared on tab
  switch.
- **Bug:** the "forgot password" email link had nowhere to go — clicking it
  landed back on the login page with no way to actually set a new password.
  Added a working recovery panel.
- **Bug:** the shared alert box lived inside the login panel, so any message
  shown while another panel (like the new password-recovery panel) was open
  would be invisible. Moved it to a shared location.

## `pages/admin.html`

- **Security/bug:** replaced the hard-coded `ADMIN_EMAIL` / `ADMIN_PASS`
  constants with real Supabase Auth sign-in, session persistence across page
  reloads (previously every refresh forced a fresh "login"), and a proper
  sign-out that logs the event first.
- **New — "Atividade" section:** admins can now see a real, filterable feed
  of admin actions *and* client signup/verification/login/logout events —
  this is the core of the requested activity-visibility feature.
- **New:** the dashboard's "Atividade Recente" panel now shows real recent
  activity instead of six permanently hard-coded fake entries.
- **Bug:** rejecting an application (from either the table row or the detail
  modal) never wrote an entry to `activity_log`, while approving did — so the
  audit trail was asymmetric. Fixed in both places.
- **Bug:** every data table (Pedidos, Clientes, Empréstimos, Pagamentos,
  Mensagens) silently kept its hard-coded demo rows on screen whenever the
  real Supabase query returned zero rows — a fresh/empty database looked
  populated with fake activity. All five now show a proper empty state.
- **Bug:** the "👁 Ver" button on every client row, and every loan row, always
  opened the *same* static modal showing the same demo client ("Maria
  Santos") regardless of which row was clicked. Both modals are now wired to
  the actual clicked record.
- **Bug:** "Novo Pedido de Crédito" and "Novo Cliente" modals didn't save
  anything at all — they just closed and showed a fake "success" toast. Both
  now actually create real records (via the new RPCs) and refresh the
  relevant table.
- **Bug:** the unread-messages sidebar badge was hard-coded to `3` and the
  code that was supposed to update it only ran when the real count was
  greater than zero — so it could never show `0` or update correctly. Fixed
  to always reflect the real count and hide when zero.
- **Bug:** dashboard stat cards were selected with a page-wide
  `document.querySelectorAll('.stat-card .stat-num')` and updated by numeric
  index — fragile, and would have silently misaligned the moment any other
  section (Payments, Newsletter) had its own stat cards, which they now do.
  Scoped the query to the dashboard section only.
- **Bug:** the Payments section's three stat cards (`€187K` / `€12.4K` /
  `€42.8K`) were permanently hard-coded and never reflected real data. Now
  computed from real payments/loans data.
- **Bug:** the Newsletter section's subscriber table was 100% static fake
  rows with non-functional delete buttons, and the "open rate"/"campaigns
  sent" stat cards showed fabricated numbers for a campaign-sending feature
  that doesn't exist in the app. The subscriber table is now wired to real
  data; the other two cards are labeled honestly as not-yet-available rather
  than showing made-up numbers.
- **Bug:** a `data-client-id` attribute on the payment-loan dropdown was
  always empty (the field was never fetched by the query it depended on) and
  was never actually read anywhere — dead, misleading code. Removed.
- Removed a fake, non-functional pagination footer ("A mostrar 10 de 47
  resultados" with buttons that had no click handlers).
- Removed the visible admin password hint from the login screen.

## Footer/legal pages (`pages/*.html`)

- **Bug:** nine pages linked from the site footer — Privacidade, Termos,
  Cookies, Reclamações, Responsabilidade Social, Parceiros, Imprensa,
  Carreiras, and Sobre Nós — were completely empty (0 bytes), i.e. broken
  links. All nine now have real, appropriately-scoped content matching the
  site's design.

## New capability delivered end-to-end

- **Client accounts:** create account → email verification → login → logout,
  all backed by real Supabase Auth (`pages/login.html`).
- **Admin visibility:** every one of those events, plus every admin action,
  is now visible and filterable in **Admin → Atividade**, and summarized on
  the dashboard's recent-activity feed.
- **One-paste database reset:** `creditxa-supabase.sql` is now the single
  file to run — it always rebuilds a clean, fully-configured database from
  scratch, including the admin panel's backing tables.
